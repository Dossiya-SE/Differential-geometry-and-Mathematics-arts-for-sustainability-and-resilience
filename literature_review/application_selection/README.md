# Application Selection

This directory records the exploration that must precede selection of the project's application domain.

- `DECISION_STATUS.yaml` is the controlling machine-readable statement of what has and has not been selected.
- `CANDIDATE_REGISTER.csv` distinguishes broad search families from sufficiently specified application candidates.
- [`scope_review_01/`](scope_review_01/) contains the Phase-0 landscape review: 12 families, 60 searchable subscopes, 42 curated anchor records, and the exact 64-query discovery log.
- The governing method is [`../protocol/APPLICATION_DOMAIN_SELECTION.md`](../protocol/APPLICATION_DOMAIN_SELECTION.md).

Entries in the register are not endorsements or rankings. `SEARCH_FAMILY` rows define where evidence will be sought. A row becomes an `APPLICATION_CANDIDATE` only when its system, stressor, outcome, scale, mathematical role, data pathway, validation pathway, and visual role are sufficiently specified for eligibility assessment.

The Phase-0 review identified a provisional **bridge deficit**: within its curated anchors, no single paper jointly operationalizes explicit differential geometry, quantified sustainability, quantified resilience, and a validated mathematical-art function. This is a corpus-limited finding, not a claim that such work cannot exist.
