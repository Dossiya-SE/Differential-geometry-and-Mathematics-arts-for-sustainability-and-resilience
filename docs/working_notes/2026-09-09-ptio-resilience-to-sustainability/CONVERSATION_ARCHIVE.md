## 2. Canonical mathematical hierarchy

The footer hierarchy is frozen as:

```math
(\mathcal G,Y,Z) \rightarrow \mathcal C \rightarrow (Z,F,J,\tau) \rightarrow (\mathcal H_{\rm obs},\hat Y,I,O,\pi,u) \rightarrow (K,\mathcal V) \rightarrow R \xrightarrow{\mathcal T_{ST}} S
```

The figure should not add explanatory subtitles beneath this chain unless they are explicitly re-approved.

## 3. Scientific domain separation

The visual must make the following separation explicit:

```text
Stages 1–5 = Resilience analysis
Stage 6     = Translation interface
Stage 7     = Sustainable transformation
```

Equivalently:

```text
Resilience domain → translation → sustainability domain
```

This is one of the framework's principal scientific messages.

## 4. Stage-by-stage visual encoding

### Stage 1 — Multilayer Structure
- Keep the exact role: **P–T–I–O architecture**.
- If four layers are drawn, label them **Power**, **Transportation**, **Information**, and **Organization**.
- Do not redefine `I` as only ICT or `O` as “others.”
- Recommended visual: four-layer interdependent network with cross-layer links.

### Stage 2 — Causal Mechanisms
- Exact role: **Cross-layer cause-effect pathways**.
- Use one directed causal network only; avoid redundant mini-networks.
- The visual should emphasize direction, dependency, and propagation.

### Stage 3 — Coupled Hybrid Multiscale Dynamics
- Exact role: **Coupling + continuous dynamics + discrete events + timescales**.
- Recommended visual: continuous trajectories combined with marked discrete events and explicit timescale markers such as `τ₁, τ₂, τ₃`.
- The point is not merely time series; it is hybrid evolution across multiple timescales.

### Stage 4 — Feedback & Control
- Exact role: **Information, organization, decisions, intervention**.
- Preferred canonical block logic:

```text
H_obs → Ŷ → I → O → π,u
```

- Close the loop back to the coupled system to show response and intervention.

### Stage 5 — Viability
- Exact role: **Survival/recoverability under constraints**.
- Use only the canonical objects **K** and **V** in the main visual.
- If coordinates are shown, use **Y₁, Y₂**, not `X₁, X₂`.
- Safe interpretation:

```text
Y(t) ∈ V ⊆ K
```

- Do not add geometry-heavy notation such as `∂V` unless explicitly re-approved.

### Stage 6 — Resilience-to-Sustainability Transformation Interface
- Exact role: **Translate resilience findings into transformation requirements**.
- Treat Stage 6 as a narrow translation/interface zone, not as a generic Venn diagram of resilience and sustainability.
- Remove unapproved additions such as “trade-offs, synergies and co-benefits” from the canonical figure.

### Stage 7 — Sustainable Transformation Pathways
- Exact role: **Technical, organizational, environmental and policy transformation**.
- Use the same **Y₁, Y₂** state-space convention as Stage 5 when coordinates are retained.
- A clean transformation visual is:

```text
Y₀  --T_ST-->  Y*
```

- Infrastructure, organizational, environmental, and policy icons may be secondary visual cues, but they must not introduce new scientific variables.

## 5. State-coordinate correction: X₁,X₂ → Y₁,Y₂

The original visual used `X₁` and `X₂` as generic state-space coordinates. The framework, however, already fixes the state object as `Y` in the canonical hierarchy. Therefore the corrected notation is:

```text
X₁, X₂ → Y₁, Y₂
```

Interpretation:

```text
Y(t) ∈ R^n  →  (Y₁,Y₂) ∈ R²
```

Recommended caption:

> **Y₁,Y₂: illustrative coordinates of a two-dimensional projection of the coupled system state Y.**

Stage 5 and Stage 7 should use the same `(Y₁,Y₂)` convention. Do not prematurely define `Y₁` as power performance and `Y₂` as transportation performance unless the mathematical model later fixes those meanings.

## 6. Title and wording corrections from the draft

The early draft title “CANONICAL 7-STAGE P-T-I-O RESILIENCE-TO-SUSTAINABILITY FRAMEWORK” was treated as a framework label rather than the thesis-grade title. The corrected title used for the design is:

**Causal–Hybrid Multilayer Resilience-to-Sustainability Framework for Interdependent Power–Transportation Systems**

Other required wording corrections:

- Stage 1: remove “(power, transport, ICT, others)” from the role text.
- Stage 5: remove `∂V`, “safe state,” and “at-risk state” from the frozen canonical content.
- Stage 6: remove “Trade-offs, synergies and co-benefits.”
- Remove explanatory subtitles under the bottom mathematical hierarchy.
- Remove the top strapline “COUPLED INFRASTRUCTURE • SYSTEMS THINKING • RESILIENT & SUSTAINABLE FUTURES.”
- Remove the bottom strapline “PEOPLE • INFRASTRUCTURE • DATA • RESILIENCE • SUSTAINABILITY” and the “SYSTEM OF SYSTEMS…” slogan.

## 7. Items explicitly not to add to the canonical figure

Unless re-approved, do not add:

- SDG icons or SDG numbering;
- extra pathway variables;
- extra resilience metrics;
- extra application outputs;
- non-frozen symbols such as `S_T, S_O, S_E, S_P`;
- geometry-heavy symbols such as `∂V`;
- explanatory subtitles under the mathematical hierarchy;
- additional scientific claims inferred only from visual decoration.

## 8. Visual design system

The preferred visual language established in the conversation is:

- white background;
- blue/navy for Stages 1–5;
- a narrow teal transition for Stage 6;
- green for Stage 7;
- central tree/branch motif retained because it communicates progression and transformation clearly;
- uniform rounded stage panels;
- standardized stage numbering and icons;
- consistent serif academic typography;
- equal margins, consistent border widths, and restrained shadows;
- no people or stock-photo imagery;
- engineering mini-diagrams rather than decorative illustrations.

The key rule is:

> **CHANGE THE VISUAL HIERARCHY, NOT THE SCIENTIFIC CONTENT.**

## 9. How the Visual ML Maths resource pack informed the framework design

The uploaded “10 Sites That Make ML Maths Click” resource pack emphasized interactive visualization of abstract mathematical objects. The useful design lesson for the thesis framework was not to copy ML imagery, but to make mathematical behavior visible.

The resulting visual grammar is:

```text
Object → interaction → motion → boundary → response
```

Applied to the thesis framework:

```text
Multilayer graph → cross-layer causality → hybrid evolution → feedback/control → viability → translation → transformation
```

Especially relevant resources discussed were:

- Setosa — PCA, eigenvectors, conditional probability, Markov chains, OLS;
- Immersive Linear Algebra — vectors, matrices, determinants, eigenvectors;
- Matrix Calculus for Deep Learning — gradients, Jacobians, chain rule;
- TensorFlow Playground — parameter changes made visible through changing boundaries;
- CNN Explainer, GAN Lab, Transformer Explainer, and LLM Visualization — examples of exposing internal mathematical operations visually.

The thesis analogue is to show how a disturbance changes state evolution, how the system approaches viability limits, how control acts, and how sustainable transformation changes the long-term pathway.
